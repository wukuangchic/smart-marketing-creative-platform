# 项目记忆与交接

**更新日期：2026-11-08**

## 项目定位

为广告公司员工提供内部创意图片生成工作台。界面和创作流程参考 DSH Image Gen；本项目是独立 Web 平台，没有把 DSH 插件作为代码底座。

首期范围：

- 文生图、单张原图图生图。
- 百炼 Qwen Image 3.0 Pro 与 Gemini 3.1 Flash Image 并排比较，共用提示词和兼容参数。
- 共享历史、逐次成本估算、账单周期汇总、管理员配置和飞书白名单。
- 收入核算与媒体广告 API 暂缓。

## 当前实现

- Next.js / TypeScript 模块化单体，PostgreSQL 保存业务记录，pg-boss 使用数据库队列，Docker Compose 部署。
- 模型调用独立运行；一家模型失败不影响另一家。超时或状态不明时不自动重试，避免重复计费。
- 原图和结果保存在服务器数据盘；图片长期保留。80% 提醒、95% 阻止新生成任务。
- 飞书 OAuth、回调和首位管理员登录已验证。两位引导管理员的 Open ID 保存在服务器环境中，不记录在仓库。
- 管理员入口为“API 配置”。在“飞书白名单”中添加后续员工，角色默认“成员”；仅授权管理员可管理 API、价格、汇率、账单和成员。
- DSH Image Gen 只作为 UI/交互参考；代码未从该项目复制。

## 未完成配置与业务边界

- 百炼、Gemini 的模型 API Key、Endpoint 和价格尚未录入，因此生产环境暂不能真实生成图片，也没有有效的逐次成本金额。
- 百炼和 Google Cloud Billing 账单只读连接尚待凭证和筛选范围；实际汇总账单不拆分成单张图片的实际费用。
- 需要配置独立于服务器的数据备份目标并完成恢复演练。
- 收入按广告消耗比例核算，客户间比例不同；正式数据源、规则和结算周期尚未确定。不要按图片数量或固定单张售价实现收入公式。
- 后续媒体 API 的平台、调用范围与授权方式待确认。

## 隐私与仓库边界

GitHub 仓库现为公开仓库；发布前已从当前文件和可达 Git 历史清除服务器公网地址、安装路径和数据盘设备标识，并检查常见密钥格式。仓库只保存应用代码、模板和不含生产值的部署示例。飞书 App Secret、管理员 Open ID、模型/账单凭证、数据库密码、加密密钥、服务器公网地址、SSH 私钥、TLS 私钥和生产图片均只保存在服务器或本机未跟踪配置中。后续改动仍须遵守此边界。

## 建议的下一步

1. 由管理员在“API 配置”录入并启用模型 API 凭证、Endpoint、价格和生效汇率，然后各做一次小额生成验证。
2. 让第二位管理员首次登录；新员工由管理员在网页白名单中添加为“成员”。
3. 配置独立数据库和图片备份，并完成恢复演练。
4. 取得账单只读凭证后，启用百炼和 Google Cloud Billing 对账。
5. 再确认收入统计口径和媒体 API 接入范围。
