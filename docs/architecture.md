# 架构说明

## 主要对象

- `GenerationRequest`：模式、提示词、参考图、模型选择和共同参数。
- `GenerationTask`：一次员工提交的任务；图生图只接受一张输入图，可关联多个团队分类标签。
- `generation_task_tags`：任务与共享分类标签的多对多关系；迁移时把旧 `generation_tasks.tag_id` 数据复制进来。
- `GenerationTask.identifier`：新任务保存 4 位提示词前缀；复用历史提示词时沿用其最近前缀，否则生成新的随机前缀。旧任务仍保留原 6 位标识。
- `GenerationTask.name_template`：图片命名模板可添加自定义前后缀，且必须且只能包含一次 `{标识}`；worker 将标记替换成该图片的完整编号。
- `MediaAsset.identifier`：新生成的每张图片使用 8 位 Crockford Base32 编号，前 4 位为提示词前缀，后 4 位为该前缀下连续分配的图片序号。文件名按命名模板保存完整编号。
- `prompt_sequences`：按提示词前缀维护下一个 4 位序号，在创建任务的数据库事务内锁定并预留所有模型的图片序号范围；单模型失败也不会回收已预留序号。
- `CreativeTag`：团队共享的可复用分类标签；任务删除不会删除标签。
- `ProviderRun`：一个模型的一次调用。对比任务为每家模型创建独立调用，单家失败不影响另一家。
- `UsageRecord`：供应商返回的用量、输出尺寸、请求 ID 和原始用量字段。
- `InvoiceRecord`：按供应商账号、账单周期及账单项目保存的汇总数据。

## 请求与任务

1. 浏览器先调用 `POST /api/generations/estimate`，服务端读取当前启用价格及生效汇率；用户在弹窗确认后，浏览器以 `multipart/form-data` 调用 `POST /api/generations`。
2. 服务端验证飞书登录、明确的确认标志、图片格式与大小、模型是否启用、模型张数能力及磁盘 95% 停止阈值。
3. PostgreSQL 事务创建带提示词前缀和可选标签的任务、输入素材和模型调用记录；按前缀连续预留图片序号，并为每个模型调用保存自己的序号起点，pg-boss 为每个模型调用单独入队。
4. worker 调用模型、立即下载供应商临时图片并保存到数据盘，写入用量和估算成本。
5. `GET /api/generations/:id` 返回任务和每家模型的独立状态。网络错误、超时或进程中止统一保留为待核实状态，不自动重发。
6. 服务端按目标宽高选取供应商支持的原生输出档位。图片返回后使用 Sharp 等比填充并裁切，保存为用户填写的精确宽高。

## 分类标签、历史下载与素材库

- `GET /api/tags` 返回团队共享标签；`POST /api/tags` 由登录成员创建或复用同名标签，大小写不敏感。
- 创作提交可关联多个标签；历史记录和素材库展示该套创作的全部标签，素材库按所选单个标签筛选；历史记录为每张生成图片提供使用 `media_assets.original_name` 的单张下载。
- `/materials` 只展示生成结果，不展示图生图输入图。`GET /api/materials` 支持按标识、生成日期和标签筛选，并分页返回缩略图元数据。
- `POST /api/materials/download` 接受已选结果 ID，验证全部均为生成素材后流式打包 ZIP；每批最多 100 张、总文件大小最多 500 MiB。

## 历史提示词重构

- `GET /api/prompts?search=...` 从共享创作历史中搜索去重后的提示词，并返回该提示词最近使用的编号前缀；员工可选择多条输入重构，也可对单条提示词点“直接使用”以原样复用并延续前缀。
- `POST /api/prompts/rewrite` 使用服务端 DeepSeek 凭证调用 `deepseek-flash`。提示词正文只发给供应商用于本次调用，不写入 API 审计日志；日志保留操作者、所选数量、字符数与返回用量。
- DeepSeek 重构会产生新提示词，不沿用输入提示词的前缀。
- 此 API 是单独的用户发起请求，不会在图片生成流程中自动重试。

## 权限

- 飞书登录后必须命中数据库白名单。首位管理员通过 `BOOTSTRAP_ADMIN_OPEN_IDS` 引导，之后可在后台维护员工和管理员。
- 所有有效白名单成员可查看共享历史、图片和成本汇总。
- 仅管理员可修改模型/API 凭证、维护成员、调整汇率、同步账单或删除任务。
- API 密钥以 AES-256-GCM 密文存储，页面只返回是否已配置；普通用户不能访问 API 配置接口。
- 删除任务时审计记录先与任务删除在同一事务中提交；素材元数据随任务级联删除，图片文件在事务提交后清理。worker 与删除操作通过任务行锁避免遗漏并发生成文件。

## 成本与账单

- 管理员按模型配置每张 1K / 2K 的价格和币种。成功调用时将模型单价乘以实际返回张数，保存供应商原币金额。
- 外币按调用开始日期匹配最新有效汇率换算成人民币；不追溯套用之后录入的汇率。
- 百炼 `DescribeInstanceBill` 按配置的百炼产品代码和账期获取账单项目；Google Billing 查询 BigQuery 标准费用导出，并强制设置服务名筛选。
- 账单导入采用账号、模型/账单项目、周期和币种汇总；账单周期总额与同周期估算并列展示。实际账单不归摊到单次图片。
- 账单连接器未配置凭证时不影响模型生成和逐次成本估算。

## 存储

`MEDIA_ROOT` 指向长期保留的图片目录。宿主机目录须挂载到独立数据盘。页面在 80% 用量时提醒，生成 API 在 95% 用量时返回 `507`。阈值只阻止新任务，已经开始的调用可能继续写出结果。

数据库任务状态和文件元数据保存在 PostgreSQL；图片文件不自动过期。管理员删除记录会留下审计事件。
