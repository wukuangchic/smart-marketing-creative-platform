# 架构说明

## 主要对象

- `GenerationRequest`：模式、提示词、参考图、模型选择和共同参数。
- `GenerationTask`：一次员工提交的任务；图生图只接受一张输入图。
- `ProviderRun`：一个模型的一次调用。对比任务为每家模型创建独立调用，单家失败不影响另一家。
- `UsageRecord`：供应商返回的用量、输出尺寸、请求 ID 和原始用量字段。
- `InvoiceRecord`：按供应商账号、账单周期及账单项目保存的汇总数据。

## 请求与任务

1. 浏览器以 `multipart/form-data` 调用 `POST /api/generations`。
2. 服务端验证飞书登录、图片格式与大小、模型是否启用、模型张数能力及磁盘 95% 停止阈值。
3. PostgreSQL 事务创建任务、输入素材和模型调用记录；pg-boss 为每个模型调用单独入队。
4. worker 调用模型、立即下载供应商临时图片并保存到数据盘，写入用量和估算成本。
5. `GET /api/generations/:id` 返回任务和每家模型的独立状态。网络错误、超时或进程中止统一保留为待核实状态，不自动重发。

## 权限

- 飞书登录后必须命中数据库白名单。首位管理员通过 `BOOTSTRAP_ADMIN_OPEN_IDS` 引导，之后可在后台维护员工和管理员。
- 所有有效白名单成员可查看共享历史、图片和成本汇总。
- 仅管理员可修改模型/API 凭证、维护成员、调整汇率、同步账单或删除任务。
- API 密钥以 AES-256-GCM 密文存储，页面只返回是否已配置；普通用户不能访问 API 配置接口。
- 删除任务时审计记录先与任务删除在同一事务中提交；素材元数据随任务级联删除，图片文件在事务提交后清理。worker 与删除操作通过任务行锁避免遗漏并发生成文件。

## 成本与账单

- 管理员按模型配置每张 1K / 2K 的价格和币种。成功调用时将模型单价乘以实际返回张数，保存供应商原币金额。
- 外币按调用开始日期匹配最新有效汇率换算成人民币；不追溯套用之后录入的汇率。
- 百炼 `DescribeInstanceBill` 按配置的百炼产品代码和账期获取账单项目；Google Billing 查询 BigQuery 标准费用导出，并强制设置服务名筛选。
- 账单导入采用账号、模型/账单项目、周期和币种汇总；账单周期总额与同周期估算并列展示。实际账单不归摊到单次图片。
- 账单连接器未配置凭证时不影响模型生成和逐次成本估算。

## 存储

`MEDIA_ROOT` 指向长期保留的图片目录。宿主机目录须挂载到独立数据盘。页面在 80% 用量时提醒，生成 API 在 95% 用量时返回 `507`。阈值只阻止新任务，已经开始的调用可能继续写出结果。

数据库任务状态和文件元数据保存在 PostgreSQL；图片文件不自动过期。管理员删除记录会留下审计事件。
